# MuJoCo 具身机器人交互与科研数据采集平台——产品需求定义 V0.1

## 1. 为什么开发？（Why）

本平台旨在构建一个以 MuJoCo 为仿真执行核心、支持人类实时交互的具身机器人科研工作台。

平台主要服务于移动机器人 VLN 导航、VLA 近场操作，以及双臂机器人操作任务。

核心目标：

1. **仿真交互：** 允许研究人员通过键盘、鼠标、虚拟或实体主臂等交互设备实时控制仿真机器人。
2. **算法观测：** 提供统一的 3D 场景、机器人状态、传感器、SLAM、目标感知及算法运行结果的可视化。
3. **人工干预：** 支持在算法运行过程中进行观察、暂停、控制接管、人工修正和恢复，验证算法的有效性及鲁棒性。
4. **专家数据生成：** 利用 SLAM、Frontier Exploration、导航规划、IK、视觉伺服等经典算法生成任务轨迹。
5. **数据采集：** 统一记录人类遥操作、专家演示、混合控制以及模型执行数据，为后续模仿学习和 VLA 训练提供数据基础。
6. **算法验证：** 后续接入 BC、ACT、Diffusion Policy、VLA、分层 VLN 等模型，支持任务执行、实验回放及性能比较。

最终目标不是开发通用三维建模工具，而是建立一套可以持续开展机器人实验的统一交互、执行、观测、录制与评估平台。

## 2. 解决什么问题？（What）

### 2.1 多源数据观测

平台需要在统一界面中展示：

**仿真与机器人状态**
- MuJoCo 3D 场景及机器人实时状态
- 机器人关节位置、速度、执行器状态
- 机器人末端位姿、目标 TCP 与当前 TCP
- 接触、抓取与碰撞状态

**LanderPi 移动操作**
- 2D LiDAR 扫描与 SLAM 地图
- RGB 彩色图像、深度图像和近场点云
- Aurora 930 RGB-D 相机视角
- 目标检测、识别及位置估计
- 机器人可达区域、IK 可行性和抓取候选位姿
- 底盘位姿、导航目标、规划路径及执行状态

**双臂 SO101 任务**
- 双机械臂 3D 模型及关节状态
- 中央相机和左右腕部相机，共三个视角
- 两侧末端位姿及抓取状态
- 双臂动作轨迹与物体交互过程
- 双臂运动的可达性、碰撞与接触信息

所有视图需要支持统一时间轴，以便同步查看、回放及分析。

### 2.2 机器人直接交互

**底盘控制**
- 键盘控制底盘前进、后退及转向
- 支持底盘速度控制与停止操作
- 支持自动导航和人工控制之间的切换

**机械臂关节控制**
- 鼠标选择指定关节进行操作
- 展示关节运动限制及当前角度
- 提供关节数值输入等辅助控制方式

**机械臂 TCP 控制**
- 在 3D 场景中选择机械臂末端
- 使用平移、旋转控制器指定目标位姿
- 实时展示目标是否可达
- 支持实时执行与预览确认两种方式
- 当目标超出机械臂自由度或工作空间能力时，反馈受限自由度及失败原因

**双臂主从遥操作**
- 支持虚拟或实体主臂作为控制输入
- 将主臂动作映射到 MuJoCo 从臂
- 显示主从状态和控制误差
- 记录主臂命令与从臂实际执行状态

### 2.3 任务与控制

平台提供统一的任务运行管理能力，包括：
- 场景加载与重置
- 机器人控制模式设置
- 任务启动、暂停、继续和终止
- 人工控制与算法控制的切换
- 算法运行状态与执行结果查看
- 人工干预事件和异常事件记录

平台应区分：

**观察/编辑阶段：** 用户配置场景、调整机器人、指定目标及检查任务条件。

**任务运行阶段：** 机器人执行动作，传感器产生数据，算法更新控制指令，录制模块持续采样。

任务运行时可以根据控制权限执行人工干预，但不能让多个控制源无约束地同时操作同一组执行器。

### 2.4 数据采集与回放

平台记录：
- 场景、机器人、任务和算法配置
- 传感器观测数据
- 机器人状态与控制命令
- 人类遥操作指令
- 专家算法输出
- 模型策略动作
- 人工接管、干预、异常及恢复事件
- 任务成功或失败的评价结果

平台应支持同步轨迹回放、数据检查、有效片段筛选及标准格式导出。

数据类型包括：
- Human Demonstration（人类演示）
- Expert Demonstration（专家算法演示）
- Intervention Trajectory（人工干预轨迹）
- Policy Rollout（学习策略执行轨迹）

后续可根据任务定义转换和导出为 LeRobot 等训练数据格式。

## 3. 产品边界在哪里？（Boundary）

### 3.1 产品责任范围

平台负责：

1. MuJoCo 仿真运行与场景管理。
2. 机器人统一控制接口及控制权限管理。
3. 传感器数据采集、同步和可视化。
4. 3D 直接交互、状态显示和任务操作界面。
5. 专家算法和学习策略的接入与运行编排。
6. 轨迹记录、回放、整理和导出。
7. 实验任务配置、执行状态记录和结果评估。
8. 人工干预及干预前后状态的记录和分析。

### 3.2 不作为当前产品的主要开发范围

- 从零开发物理仿真求解器。
- 实现通用 3D 建模编辑器。
- 从零实现所有 SLAM、导航、视觉检测和机械臂控制算法。
- 自行开发完整的大模型训练框架。
- 在第一阶段支持所有机器人型号或所有任务类型。
- 在第一阶段实现真实机器人硬件控制和部署。

上述能力可以复用已有开源项目或通过独立模块扩展。

### 3.3 两条核心任务线

**任务线 A：LanderPi 移动操作**

支持具有移动底盘、机械臂及环境感知传感器的机器人。

任务能力分为：
- 地图构建与环境探索
- 目标检测和空间定位
- 导航及目标抵近
- 机械臂可达性和抓取姿态计算
- 视觉伺服与底盘辅助调整
- 抓取执行、验证和数据录制

**任务线 B：SO101 双臂操作**

支持固定基座的双臂机器人，不涉及移动底盘导航。

任务能力分为：
- 关节直接控制
- TCP 目标控制
- 主从臂遥操作
- 双臂动作规划
- 方块传递、拾取和装配等操作
- 抓取及接触验证
- 双臂轨迹录制

两条任务线共用仿真、机器人状态、控制接口、可视化、任务管理、数据录制及实验评估基础设施。

## 4. 有哪些核心对象？（Core Objects）

| 对象 | 定义 |
|---|---|
| Scene | 仿真场景、物体、障碍物和初始条件 |
| Robot | 底盘、机械臂、末端执行器及机器人整体状态 |
| Sensor | RGB、RGB-D、LiDAR 等观测数据来源 |
| Simulation Session | 一次仿真运行及其时间、状态和生命周期 |
| Task | 导航、抓取、传递、装配等任务目标和成功条件 |
| Controller | 人类遥操作、经典专家控制器或学习策略 |
| Algorithm Run | SLAM、导航、视觉检测、IK 等算法的运行实例 |
| Observation | 带时间戳的传感器与机器人状态观测 |
| Trajectory / Episode | 从任务开始到结束的一段执行过程 |
| Experiment / Dataset | 实验配置、测试结果与采集数据集合 |

其中 Controller 提供统一控制接口，允许机器人接受不同来源的动作指令。

Task 定义任务目标及验收条件，而不是简单对应某个界面按钮。

Trajectory 记录实际执行过程，并保留动作来源、观测、状态及干预信息。

## 5. 用户如何完成完整任务？（User Workflow）

### 5.1 LanderPi 移动抓取任务

**阶段 A：实验准备**

1. 用户选择 MuJoCo 场景和 LanderPi 模型。
2. 配置传感器、任务目标、算法和初始状态。
3. 选择人工控制、专家算法或混合控制。
4. 检查设备状态并启动仿真。
5. 开始数据记录。

**阶段 B：导航与环境探索**

1. 获取 RGB、深度、LiDAR 和机器人里程计数据。
2. 根据实验配置运行 SLAM。
3. 使用键盘控制、Frontier Exploration 或自动导航探索环境。
4. 在地图和 3D 视图中观察建图与定位结果。
5. 记录导航动作及环境观测。

**阶段 C：目标搜索和接近**

1. 机器人进入目标搜索或观察模式。
2. 控制底盘或相机进行扫描。
3. 运行目标检测算法。
4. 利用相机标定、深度和机器人位姿估计目标位置。
5. 根据定位结果计算目标相对底盘的方向和距离。
6. 通过规划或视觉反馈控制底盘接近目标。
7. 检查机械臂工作空间及抓取可达性。

**阶段 D：近场操作和抓取**

1. 根据 RGB-D 及机器人状态估计目标抓取位姿。
2. 通过正运动学确定当前 TCP，通过 IK 计算候选关节目标。
3. 检查目标可达性、碰撞和运动约束。
4. 控制机械臂向预抓取位置运动。
5. 通过视觉伺服持续修正目标和 TCP 之间的误差。
6. 必要时小幅调整底盘位置。
7. 执行夹爪闭合和物体抬升。
8. 利用接触状态、物体运动、抬升高度及保持状态判断抓取结果。

**阶段 E：人工干预及鲁棒性验证**

1. 用户可在允许的阶段接管底盘或机械臂控制。
2. 人工修正姿态、目标位置或执行路径。
3. 平台记录接管起止时间、动作来源及相关状态。
4. 根据实验规则继续执行、恢复算法控制或重置任务。
5. 比较干预前后的算法表现。

**阶段 F：实验结束**

1. 执行任务成功/失败判定。
2. 保存轨迹、观测、控制命令及事件。
3. 使用统一时间轴回放。
4. 检查和标记有效数据。
5. 导出专家数据或模仿学习训练数据。

### 5.2 SO101 双臂操作任务

**阶段 A：实验准备**

1. 加载 MuJoCo 双臂机器人场景。
2. 检查双臂初始关节及夹爪状态。
3. 启用中央相机和两个腕部相机。
4. 选择控制模式。
5. 指定方块传递、抓取或装配任务。

**阶段 B：机器人操作**

根据需要选择：

- 鼠标直接调整关节。
- 鼠标控制双臂末端目标位姿。
- 使用主臂实时遥操作仿真从臂。
- 启用 IK 与运动规划专家。
- 后续启用 ACT、Diffusion Policy 或 VLA 策略。

**阶段 C：任务执行和观察**

1. 执行目标接近、抓取、移动及交互。
2. 实时查看机器人和三路相机观测。
3. 检查双臂关节、TCP 和夹爪状态。
4. 显示接触、碰撞和任务进度。
5. 支持人工控制与算法控制之间的安全切换。
6. 根据任务条件判断动作和任务是否成功。

**阶段 D：数据记录与评估**

1. 记录同步视觉观测、关节状态、动作目标和实际执行状态。
2. 区分主臂输入、专家控制和模型输出。
3. 检查抓取和物体传递结果。
4. 回放并筛选有效轨迹。
5. 整理为可用于后续 ACT、BC 或其他策略训练的数据集。

## 6. 统一设计原则

1. **统一仿真状态：** MuJoCo 是仿真物理状态的权威来源，前端通过控制命令影响仿真，而不是直接覆盖物理状态。
2. **统一控制接口：** 人类、专家算法和学习策略通过统一的控制契约驱动机器人。
3. **统一时间轴：** 机器人状态、传感器、动作与事件都需要可同步追溯。
4. **算法与界面解耦：** 算法计算和 3D 可视化独立运行，通过明确的数据接口连接。
5. **统一任务管理：** 不同任务复用相同的启动、暂停、接管、恢复、停止、重置和评价机制。
6. **数据可复现：** 保存足够的环境、控制、算法及随机性配置，以支持实验复现。
7. **人机协同：** 人类不仅是控制输入来源，也是能够干预、修正及验证算法的实验参与者。
8. **逐步扩展：** 首先实现两条核心任务线，再扩展更多算法、机器人及数据集格式。

## 7. 第一阶段成功标准

第一阶段至少能够：

- 加载并运行 LanderPi 和 SO101 的 MuJoCo 场景。
- 通过键盘或鼠标实现机器人基础遥操作。
- 可视化相机、机器人状态和基础感知结果。
- 使用统一接口接入至少一种专家控制流程。
- 完成各任务线至少一条可重复的完整操作流程。
- 同步记录观测、动作、状态及任务事件。
- 回放已记录的轨迹，并验证记录结果。
- 区分人工动作、专家动作及人工干预事件。

第一阶段的交付重点是：**证明统一交互、任务执行和数据记录链路能够闭环工作。**
