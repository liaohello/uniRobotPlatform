# 阅读指南与分类依据

建议采用“前端按业务工作区＋共享交互，后端按能力域”的混合组织，界面区域和机器人类型作为辅助索引。

## 为什么不只按左中右分类

关节监控可以从右栏移到浮窗，TCP 工具也会被场景、仿真和回放复用。若把位置作为主目录，改布局就需要搬规则，也容易在多个页面重复定义交互。

## 三类入口

| 想解决的问题 | 从哪里读 |
|---|---|
| 我要设计某个业务流程 | 工作区索引 → 对应前端功能包 |
| 我看到界面某个区域，不知道规范在哪里 | 界面区域索引 → 主责节点 |
| 我要让功能前后端接通 | 功能映射 → FE / BE / CT / TEST |

## 每层文档应该多大

大类 README 只做导航；功能包 README 解释目标、节点和依赖；编号节点是实际讨论和维护单位。节点内可再列子规则，只有可独立验收的复杂内容才继续拆文件。分类深度通常保持三层，不按每个控件建立文件。

## 当前注意事项

当前按四导航组组织六个逻辑职责的方案继续细化，训练与评估仍是概念设计；滑条主要监控、显式接管，以及 S10 新增的 Scene Setup Waypoint 编辑等用户修订应优先。后端和 API 未决内容继续标为草案。
