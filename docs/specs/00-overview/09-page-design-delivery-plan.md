## 首条真实任务链

当前验收链为 mobileCar Scene Setup → Run → Recording → Replay；完整清理/数据版本/训练/预测保留为后续目标。详细阶段在 [当前基线](10-first-task-closed-loop.md) 定义，辅助资源页可以仅提供已有预设选择，轻量宿主不要求完整菜单。

M1 不要求真实训练/预测、Collection 发布或训练资格；这些在后续受影响阶段验收。Waypoint V1 编辑保存范围保留，运行中热重规划等不因此开放。

## M1 实施工作包

现在具备规划条件：范围、对象权威、命令/录制边界和 TEST-MOBILE-001/002 已明确。当前仍需实现准备态/Start 适配、实际 UI 和原生记录读取；这些是下面的工作，不是“已有 API”。M1.1～1.6 是同一个正式 M1 内的工作包，不额外建立一套里程碑或承诺工期。

| 工作包 / 依赖 | 输入与实现边界 | 可交付产物 | 完成检查 |
|---|---|---|---|
| M1.1 接入核对与最小技术选择 / 无 | 现有 gateway、mobileCar scene/snapshot/commands/episodes 和服务器执行政策；只选真实可用预设与人工输入路径 | 一份接口/身份/支持字段/缺口映射；固定 native 源码/配置版本和运行入口；确定最小前端构建方式 | 明确 prepared 尚缺什么、Start 怎样绑定 runtime、原生 start 的 RESET 边界；不把在线探活当完整 Ready。不为未冻结框架创建全平台依赖 |
| M1.2 最小宿主与配置准备 / 1.1 | 使用支持字段白名单；组件由 HostContext 注入 draft/能力/服务；后端解析配置并验证 | 最小 Scene Setup、草案保存/错误/过期反馈、ValidatedSnapshot 和 prepared Session 适配 | TEST-CONFIG-003/004/005/007/008 的已开放部分；准备/保存/创建不触发运动、RESET 或录制，未实现任意场景编辑明确禁用 |
| M1.3 运行与人工控制 / 1.2 | 显式 Start；复用原生租约、STOP 和 require_recording 门控，不增第二物理循环 | 最小运行视图、实际状态/必要相机、命令受理与拒绝、停止与连接状态 | 服务端确认 Session/runtime 绑定；请求/受理/到位分开；原生要求先录制时驾驶保持禁用，切页/失焦撤销持续输入，不绕过原保护 |
| M1.4 录制与结束 / 1.3 | 包装原生 episodes/start、stop 和 Recorder；不新建浏览器逐帧录制器 | RESET 提示、actual 初态与 epoch/segment 映射、配置 sidecar/index、录制状态和结束回执 | 起始内容持久化后才确认 RECORDING；RESET 受理不等于生效。停车反馈、drain/finalize 和完整性独立显示；FAILED/缺尾保留诊断，覆盖 TEST-MOBILE-002 |
| M1.5 列表与只读回放 / 1.4；只读 reader 可提前独立开发 | 原生 EpisodeReader/媒体，按 source/native identity 读取；不依赖 Dataset/Export | 最小 Episode 列表/详情、历史时间轴、状态/动作/声明必需流、缺失提示 | 结束后重新加载；即使 training_qualified=false 也能读取合格原始记录。回放不发控制、不推进物理、不改原始文件；部分损坏明确展示限制 |
| M1.6 整体验收与交付 / 1.2～1.5 | 同一冻结配置、真实 runtime 和原生记录；人工行为由真实操作者完成 | TEST-MOBILE-001/002 及适用配置测试的证据、已知限制、源码/配置/数据身份和复现入口 | 至少一条真实场景→运行→录制→重载回放，另验失败/Reset；任务成功、停车、录制完整性和训练资格不混为一项；通过后结束 M1，再进入 M2 |

主负责人维护共享契约、应用装配和公共依赖，具体文件单一写入者；只读子代理可并行定位接口/复核证据。M1.5 的 reader 研究可以和配置 UI 并行，但依赖 native 身份/终态的整体验收必须等待录制链完成。

本仓库现有 `backend/src/unirobot` 是网关基础，接入在其契约边界逐步补齐；前端构建与目录在 M1.1 固定，不从图片或空目录推断已经存在应用。mobileCar 核心控制/录制/物理代码优先复用，仅在明确适配差距需要时调整对应边界，不整体搬库或统一 MuJoCo 版本。

涉及 mobileCar 的安装、前端构建、lint/typecheck、单元/集成测试、仿真、渲染、自动浏览器和数据导出均遵守其 [服务器执行政策](../../../../mobileCar/docs/server_execution_policy.md)；连接信息不进入规范或 Git。本次仅制定计划和检查文档，不执行上述产品工作。

## M2 与后续范围

M1 通过后再让 bimanual 注入不同能力、相机/动作单位、命令和记录 reader，执行 TEST-HOST-001 并核对复用边界。先复用真正需要的组件/协议，不把旧工具全部改造成一个宿主或提前建设插件平台。

Collection/Dataset Version、模型 IO/processor、训练/预测在后续单独规划；它们既不作为 M1 完成条件，也不因为此计划而被取消。验收定义以 [QA-SCENE-FIRST-LOOP](../40-verification/06-scene-setup-first-loop.md) 为准，当前状态仍全部待执行。

## Specification 的迭代时点

开始任务前细化相关页面、功能、契约与验收；实现中发现能力不匹配立即更新对应主责条款并记来源；完成后记录真实结果和与图的差异，再开始下一条任务。不要每次重写整套总册，也不要等子任务全部结束才改规范。

页面、共享组件、后端/契约和证据分别维护。每个任务结束只更新受影响节点、图片映射、决策和测试状态；历史原图与来源不被覆盖为新事实。
