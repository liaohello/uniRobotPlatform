首先落实只读执行：

1. 历史验证只访问平台 GET 和归档只读文件；确需 native health 时统一使用不接受 method/body 参数的 GET-only 探测入口，人工排障也遵守；禁止真实 native validate/assessment POST 及临时写探测；需要重算结论只能在隔离副本中执行。
2. 保留违规记录与当前派生报告，不覆盖、删除或猜测回滚；修正文档中超出证据的"所有原始文件未改"等表述；后续验证预先记录实际覆盖文件的摘要，复核同一集合并明确未覆盖范围，不把局部摘要扩写为整个归档不变性证明。

修复：

3. 统一受限路径解析：recording root、run、episodes 目录、Episode 目录、run manifest、episode/tail/sidecar、固定 stream 与 assets 的解析结果必须满足对应来源与 Episode 边界；索引和实际读取都不能借目录或文件软链越界；缓存索引不能绕过读取时检查；使用最小公共路径检查，不搭建通用文件系统沙箱。
4. 修复 `event_seq` 过滤：范围过滤启用时，缺失、非整数及 bool 序号不能通过，按契约排除并报告数量，不补造序号；保持合法数据的分页、`next_offset`、原始顺序和身份语义，不以行号冒充事件序号或时钟。

重新冻结：

5. 完成代码与检查工具修改后生成新的不可变 release；清单覆盖 src/config/tools 及实际启动器；冻结后不再原地修改源码或检查工具；保留旧 `58a737…` 及旧报告作为历史证据，不倒填为新摘要；新启动清单、实际字节、检查工具、报告和提交逐一对应。

## 多 agent 约定

主智能体负责决策、修改、服务器验证与整合；`default`、`fork_turns=none`，最多 3 个只读子 agent：A 核查 run/Episode/固定文件/资产的路径边界；B 核查 records 分页、`event_seq` 与时间过滤契约；C 核查违规影响证据、冻结身份与报告绑定。子 agent 不写文件、不执行测试/构建/安装、不派生 agent。
